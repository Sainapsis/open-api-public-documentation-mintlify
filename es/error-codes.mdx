<a id="response-format"></a>

## Formato de respuesta

Ejemplo de respuesta `Problem`. Consulta la referencia del endpoint para conocer su estado HTTP, tipo de contenido y esquema de respuesta:

```json
{
  "title": "A template named in the onboarding override is missing values only the caller can provide",
  "status": 422,
  "detail": "A template named in the onboarding override is missing values only the caller can provide",
  "code": "BRIDGE_CONVERSATION_0604",
  "extra": {
    "templateId": "f0000040-0000-4000-8000-000000000040",
    "missingVariables": [{ "key": "delivery_date", "label": "Delivery date" }]
  },
  "instance": "https://api-connect-us.bridge.new/bridge/api/v1/workspaces/{workspaceId}/conversations",
  "traceId": "Root=1-6702b8c4-3f1a2b4c5d6e7f8091a2b3c4"
}
```

| Campo | Significado |
| --- | --- |
| `code` | Cuando aparece, código estable de error incluido en esta página. **Decide qué hacer según este campo, no según el título.** Los errores de validación y del servidor pueden omitirlo. |
| `title` | Mensaje legible para personas. Puede ser más largo que el título de las tablas siguientes: nunca lo uses para identificar el error |
| `status` | Código de estado HTTP |
| `detail` | Más información sobre este caso, cuando está disponible |
| `extra` | Contexto estructurado para procesar el error, como los IDs o claves involucrados, cuando está disponible |
| `instance` | URL de la solicitud |
| `traceId` | Inclúyelo cuando contactes a soporte |

<Note>
  Lee el esquema de respuesta de la operación que llamas. Cuando sea `HTTPValidationError`, los detalles están en un array `detail`; cada entrada contiene `loc` —dónde—, `msg` —qué— y `type`. Otras respuestas `422` documentadas usan `Problem` y pueden incluir `code` y `extra`. No asumas que todas las respuestas `422` tienen el mismo formato.
</Note>

<a id="parse-validation-errors-defensively"></a>

### Interpreta los errores de validación de forma defensiva

Acepta cuerpos de error JSON con `application/json` o `application/problem+json`. Comprueba primero el estado HTTP y después revisa el cuerpo:

1. Si aparece `code`, usa la entrada correspondiente de esta página para decidir qué hacer.
2. Si `errors` es un array, lee sus entradas `loc`, `msg` y `type` como detalles de validación.
3. Si `detail` es un array, interprétalo como el formato `HTTPValidationError`. Un `detail` de tipo cadena es una explicación, no una lista de errores de campos.
4. Conserva `traceId`, el estado y la URL de solicitud para soporte. No exijas la presencia de `code` o `extra` ni uses mensajes legibles como identificadores.

Un campo inválido y una regla que relaciona varios campos no tienen por qué compartir el mismo estado. Las reglas del cuerpo saliente revisadas generan `400` con `BRIDGE_CORE_0103` cuando `consent.status` es `GRANTED` y no se incluye `capturedAt`, o cuando `template.media` proporciona ambos o ninguno de `mediaId` y `url`. Los tipos de campo o UUID inválidos pueden producir, en cambio, detalles de validación de solicitud con `422`. Interpreta juntos el estado y el cuerpo de error; no exijas un array `errors` para toda solicitud inválida.

<a id="legacy-code-strings"></a>

### Códigos heredados con sufijo

Algunos manejadores de errores heredados añaden un nombre simbólico a `code`, por ejemplo, `BRIDGE_PRELOAD_FILE_0002 | PRELOAD_FILE_IS_PENDING`. Conserva el valor recibido completo para registros y soporte. Para consultar el catálogo, acepta un código simple conocido o su forma heredada reconocida explícitamente; no compares `title` o `detail`, no inventes un código desconocido ni reescribas el cuerpo de la respuesta. Esta revisión del código fuente no ha confirmado de forma independiente qué versión del manejador está desplegada.

<Warning>
  **Compatibilidad de validación:** algunas respuestas OpenAPI publicadas declaran `HTTPValidationError.detail[]` y `application/json`, mientras que el manejador compartido de errores de la API revisado para esta documentación devuelve detalles de validación en `Problem.errors[]` con `application/problem+json`. Esta actualización editorial conserva las definiciones de respuesta publicadas. Maneja ambos formatos; sigue pendiente la confirmación contra la API desplegada antes de admitir solo uno en un cliente generado estricto.
</Warning>

<a id="decide-whether-to-retry"></a>

### Decide si debes reintentar

| Resultado | Acción |
| --- | --- |
| `400` o `422` | Corrige la solicitud según el código y los errores de campos. Repetir la misma entrada no corrige la validación. |
| `401` o `403` | Revisa las credenciales, el espacio de trabajo y los permisos del tipo de integración correcto. Guarda las claves REST en el servidor. |
| `404` | Confirma el identificador y el espacio de trabajo. Una consulta sin contacto coincidente es distinta de una entrada mal formada. |
| `409` | Lee el código de la operación: una conversación existente, un agente no disponible o una sesión pendiente requieren soluciones distintas. No habilites `forceSend` automáticamente. |
| `429` | Sigue la [guía de encabezados y espera por límite de solicitudes](/es/rate-limits). |
| Tiempo de espera agotado, respuesta desconectada o `5xx` después de una escritura | Trata el resultado como incierto. Revisa el recurso afectado antes de reenviar: un error no demuestra que no se haya guardado ningún cambio. |

Esta guía general de reintentos no agrega idempotencia a un endpoint. Para reutilización, recuperación y escrituras parciales, consulta [Conversaciones salientes y transferencias de agentes](/es/guides/agent-outbound). Custom Connections tiene su propia [referencia de errores](/es/lead-capture/errors) y no usa una clave de la API REST.

<a id="message-reply-errors"></a>

## Errores al responder a un mensaje

Para `POST .../messages`, las comprobaciones revisadas del mensaje al que respondes definen estas formas heredadas adicionales:

- `BRIDGE_MESSAGE_0001 | MESSAGE_NOT_FOUND` (`404`): no se encontró el Message indicado en `replyToMessageId`.
- `BRIDGE_MESSAGE_0002 | MESSAGE_IS_NOT_ON_CONVERSATION` (`403`): el mensaje al que respondes pertenece a otra Conversation. Usa uno de la Conversation en la que vas a enviar el mensaje.

Conserva `code` completo, incluido su sufijo simbólico. Estas comprobaciones se refieren al mensaje al que respondes, no al `mediaId` del archivo adjunto.

<a id="file-upload-errors"></a>

## Errores de carga de archivos

El flujo de carga revisado define estos códigos heredados. El sufijo forma parte del `code` recibido, no es un campo de la solicitud. Consulta el contrato de respuesta de la operación y conserva la interpretación compatible anterior.

La operación determina qué errores de archivo corresponden: `POST .../files` comprueba los metadatos y puede devolver los códigos `0003` o `0004` de abajo. `POST .../messages` puede devolver `0001` o `0002` cuando el `mediaId` de un adjunto no existe o sigue pendiente. Los archivos de las plantillas salientes tienen su propio manejo de errores; no sustituyas `BRIDGE_AI_LEADSCOUT_0016` por estos códigos.

| `code` heredado | Estado | Acción |
| --- | --- | --- |
| `BRIDGE_PRELOAD_FILE_0001 \| PRELOAD_FILE_NOT_FOUND` | 404 | Comprueba el `mediaId` devuelto y la carga a la que hace referencia. |
| `BRIDGE_PRELOAD_FILE_0002 \| PRELOAD_FILE_IS_PENDING` | 400 | El archivo sigue pendiente. Confirma que el PUT terminó y permite que se procese la carga; no deduzcas que una solicitud de Message fallida no guardó ningún cambio. |
| `BRIDGE_PRELOAD_FILE_0003 \| PRELOAD_FILE_INVALID_MIME_TYPE` | 400 | Corrige la combinación del tipo MIME y el `fileType` lógico. |
| `BRIDGE_PRELOAD_FILE_0004 \| PRELOAD_FILE_INVALID_NAME` | 400 | Proporciona un nombre con una extensión admitida para ese `fileType` lógico. |

En `POST .../conversations/{conversationId}/send-template`, `0001` y `0002` se refieren a `template.media.mediaId`. `0001`: sube el archivo con `POST .../files` y envía el `mediaId` que devuelve. `0002` cubre un archivo que aún se está subiendo y uno cuya carga se canceló, y la respuesta no dice cuál: si aún se está subiendo, termina la carga y reintenta con el mismo `mediaId`; si la carga se canceló, sube un archivo nuevo y envía el nuevo `mediaId`.

## Códigos de error de agentes

Errores de las operaciones de agentes.

| Código | Referencia en inglés | Mensaje |
| --- | --- | --- |
| `BRIDGE_AI_AGENT_OUTBOUND_0001` | Agent Not Found | No se encontró el agente en el espacio de trabajo |
| `BRIDGE_AI_AGENT_OUTBOUND_0002` | Agent Not Available | El agente no está disponible para conversaciones salientes |
| `BRIDGE_AI_AGENT_OUTBOUND_0003` | Agent Type Not Supported | El tipo de agente no admite conversaciones salientes |
| `BRIDGE_AI_AGENT_OUTBOUND_0004` | No Channels For Agent | El agente no tiene una línea activa de mensajería vinculada |
| `BRIDGE_AI_AGENT_OUTBOUND_0005` | Agent Not Assigned To Channel | El agente no está asignado al canal solicitado |
| `BRIDGE_AI_AGENT_OUTBOUND_0006` | Conversation Controlled By Other Agent | Otro agente controla la conversación activa |
| `BRIDGE_AI_AGENT_OUTBOUND_0007` | Invalid Cursor | El cursor de paginación está mal formado o pertenece a otro espacio de trabajo |

`POST .../agents/{agentId}/outbound` devuelve `0001` y `0004` como `404`, `0002` y `0006` como `409`, y `0003` y `0005` como `422`.

- `0002`: el agente está en borrador o no tiene una línea. `extra.reason` indica la causa; esa misma causa aparece en `unavailableReason` en `GET .../agents`.
- `0006`: la conversación del contacto en la línea seleccionada por la solicitud está controlada por otro agente o por un usuario de Bridge. No se envió nada. Libérala con `POST .../conversations/{conversationId}/release`, usando `extra.conversationId`, y vuelve a intentar. `extra` también incluye `channelId` y, solo si la controla un agente, `controllingAgentId`, que identifica a ese agente. Cuando la controla un usuario de Bridge, la clave no aparece; no se devuelve `null`.

`GET .../agents` devuelve `0007` como `400` cuando el `cursor` está mal formado o se emitió para otro espacio de trabajo. Empieza otra vez sin cursor. Conserva el mismo filtro `type` durante la paginación: un cursor emitido con un filtro `type` se rechaza si la solicitud usa otro `type`.

| `BRIDGE_CONVERSATION_0609` | Onboarding Required | La conversación se inició sin su plantilla inicial de WhatsApp; envía primero la plantilla inicial |
| `BRIDGE_CONVERSATION_0613` | Opening Template In Flight | La plantilla inicial aún se está enviando; reintenta en unos segundos |

Al crear una conversación, `BRIDGE_CONVERSATION_0105` devuelve `409` con `extra.reason` igual a `PARTICIPANTS_MISMATCH`: una conversación liberada ocupa la línea del contacto con otros contactos o líneas. Solicita los mismos contactos y líneas o usa otra línea.

`BRIDGE_CONVERSATION_0601` devuelve `404`, `0602` y `0603` devuelven `400`, y `0604` a `0608` devuelven `422`. Consulta [Parámetros de plantillas de inicio](/es/templates-and-parameters) para saber qué incluye cada uno en `extra` y cómo corregirlo.

`POST .../conversations/{conversationId}/send-template` devuelve estos como `409`. En ninguno se envió nada.

- `0007`: la conversación fue liberada y esta operación no la recupera. Vuelve a iniciarla con `POST .../conversations`, solicitando los mismos contactos y líneas: Bridge recupera una conversación liberada cuando puede.
- `0011`: un Agente está atendiendo la conversación. Consúltala con `GET .../conversations/{conversationId}` y reintenta cuando su `status` sea `ACTIVE`.
- `0004`: la conversación no está activa, por ejemplo porque está bloqueada o eliminada. Revisa su `status` y reintenta solo cuando sea `ACTIVE`.
- `0609`: la conversación aún no tiene plantilla inicial y esta plantilla no es de marketing ni de utilidad. Envía una plantilla de marketing o de utilidad: pasa a ser la plantilla inicial.
- `0613`: otra solicitud está abriendo la conversación con su plantilla inicial, o esa plantilla aún se está enviando. Reintenta en unos segundos: el bloqueo dura como máximo 120 segundos desde que se creó la plantilla inicial. Dos solicitudes que abren a la vez la misma conversación pendiente no pueden enviar las dos: una recibe este error, o `0406` cuando la otra tiene reservado antes el periodo de espera del contacto en un workspace que lo tiene.
- `0406`: la plantilla es de marketing o de utilidad y un contacto de la conversación está dentro del periodo de espera promocional del workspace: otro envío ya lo tiene reservado. Bridge cuenta los envíos que registró o está registrando, no si WhatsApp los entregó. `extra.contactIds` lista esos contactos y `extra.retryAfterSeconds` es la espera más larga que queda, también en la cabecera `Retry-After`. Reintenta pasados esos segundos. Dos envíos de marketing o de utilidad que compiten por el mismo contacto no pueden salir los dos: uno recibe este error.

También devuelve `BRIDGE_CONVERSATION_0001` como `404` cuando la conversación no existe en tu workspace (envía el `conversationId` de una de tus conversaciones) y `BRIDGE_CONVERSATION_0201` como `422` cuando no tiene ningún contacto de WhatsApp (envía a una conversación que tenga uno: `GET .../conversations/{conversationId}` lista sus participantes).

<a id="rate-limit-error-codes"></a>

## Códigos de error de límites de solicitudes

Errores devueltos cuando un espacio de trabajo supera su presupuesto de solicitudes. Consulta el presupuesto, los encabezados y un cliente que regula su ritmo en [Límites de solicitudes](/es/rate-limits).

| Código | Referencia en inglés | Mensaje |
| --- | --- | --- |
| `BRIDGE_RATE_LIMIT_0001` | Too Many Requests | El espacio de trabajo agotó el presupuesto de solicitudes de la ventana actual |

Este es el único código que debe reintentarse automáticamente, y solo después de la espera indicada por `Retry-After`. Los fallos de autenticación no son errores de límite de solicitudes y reintentarlos de forma programada no los resolverá.

<a id="request-error-codes"></a>

## Códigos de error de solicitudes

Errores devueltos antes de ejecutar una operación cuando la propia solicitud no se puede procesar. Consulta en el [Registro de cambios](/es/changelog) los parámetros que un endpoint dejará de aceptar.

| Código | Referencia en inglés | Mensaje |
| --- | --- | --- |
| `BRIDGE_CORE_0101` | Invalid Field Format | El formato del campo es inválido; proporciona un valor válido |
| `BRIDGE_CORE_0102` | Missing Required Field | Faltan campos obligatorios; revisa la operación |
| `BRIDGE_CORE_0103` | Bad Request | La solicitud es inválida; revisa el cuerpo y los parámetros |
| `BRIDGE_CORE_0104` | Invalid Cursor | El cursor es inválido; usa uno obtenido de una respuesta anterior |

No reintentes ninguno de estos casos sin hacer cambios. `detail` describe el problema y, cuando es posible, indica el campo o parámetro incorrecto; la misma solicitud fallará igual hasta que la modifiques.
