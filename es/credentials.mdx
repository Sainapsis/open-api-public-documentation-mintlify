<a id="overview"></a>

## Descripción general

Toda solicitud a la **API REST de integraciones** en `https://api-connect-us.bridge.new` usa una **clave de API** en el encabezado `x-api-key`. Esta clave identifica tu aplicación y la autoriza a acceder a los recursos de Bridge en nombre de tu organización.

| Tipo de integración | Manejo de credenciales |
| --- | --- |
| API REST de integraciones | `x-api-key` desde el servidor, enviada a `https://api-connect-us.bridge.new`. |
| Webhooks | Tu receptor comprueba la clave de API del webhook configurada, la firma HMAC y la política de vigencia. Sigue la guía para [verificar firmas](/es/webhooks/verifying-signatures). |
| Custom Connections | `captureKey` pública y reCAPTCHA desde el navegador; sin encabezado de autenticación. Sigue su [guía de integración](/es/lead-capture/integration). |

<Note>
  Necesitas acceso a la consola de administración de Bridge en https://admin.bridge.new.

  Si no tienes una cuenta, pídele al administrador de Bridge que te cree un usuario.
</Note>

<a id="generating-an-api-key"></a>

## Genera una clave de API

<Steps>
  <Step title="Abre la consola de administración" icon="browser" iconType="regular" stepNumber={1}>
    Ve al [panel de Bridge](https://admin.bridge.new) e inicia sesión con tus credenciales.
  </Step>
  <Step title="Ve a la administración de claves" icon="key" iconType="regular" stepNumber={2}>
    En el panel izquierdo, abre **Developers → API Keys Management**.
  </Step>
  <Step title="Crea una clave" icon="plus" iconType="regular" stepNumber={3}>
    Haz clic en **Generate New Key**. Puedes asignarle un nombre descriptivo y una fecha de vencimiento.

    <Warning>
      **Importante:**\
      Tu clave de API se muestra una sola vez al crearla. Cópiala de inmediato y guárdala en un lugar seguro; no podrás volver a consultarla.
    </Warning>
  </Step>
</Steps>

<a id="using-your-api-key"></a>

## Usa tu clave de API

Incluye tu clave de la API REST en el encabezado `x-api-key` de cada solicitud al host de integraciones REST:

```bash
curl -X GET "https://api-connect-us.bridge.new/bridge/api/health" \
  -H "x-api-key: YOUR_API_KEY"
```

```javascript
const response = await fetch("https://api-connect-us.bridge.new/bridge/api/health", {
  method: "GET",
  headers: {
    "x-api-key": "YOUR_API_KEY",
  },
});

const data = await response.json();
console.log(data);
```

```python
import requests

response = requests.get(
    "https://api-connect-us.bridge.new/bridge/api/health",
    headers={"x-api-key": "YOUR_API_KEY"}
)

print(response.json())
```

<Note>
  Usa el endpoint `GET /bridge/api/health` para comprobar que la clave de API es válida y que la conexión funciona.
</Note>

<a id="security-best-practices"></a>

## Buenas prácticas de seguridad

- **Usa variables de entorno:** guarda la clave en una variable de entorno, por ejemplo `BRIDGE_API_KEY`, en lugar de escribirla directamente en el código fuente.
- **Nunca expongas las claves en código del cliente:** las claves de API solo deben usarse en aplicaciones del servidor. Nunca las incluyas en código frontend, aplicaciones móviles ni repositorios públicos.
- **Configura un vencimiento:** establece siempre una fecha de vencimiento al crear la clave. Evita usar claves sin vencimiento definido.
- **Una clave por aplicación:** usa una clave de API distinta para cada servicio o aplicación que se conecte a Bridge. Así limitas el impacto si una clave se filtra.
- **Rota las claves periódicamente:** crea una nueva clave y actualiza tus aplicaciones antes de desactivar la anterior. Esto evita interrupciones durante la rotación.

<a id="troubleshooting"></a>

## Solución de problemas

| Error | Posible causa | Solución |
| ----- | -------------- | -------- |
| `401 Unauthorized` | La clave de API es inválida, venció o no se envió | Comprueba que la clave sea correcta, esté activa y se incluya en el encabezado `x-api-key` |
| `403 Forbidden` | La clave de API no tiene acceso al recurso solicitado | Comprueba que tenga los permisos necesarios para este endpoint |
| No puedes volver a consultar la clave de API | La clave se muestra una sola vez al crearla | Genera una nueva clave en la consola de administración |

Consulta la lista completa en la referencia de [códigos de error](/es/error-codes).
