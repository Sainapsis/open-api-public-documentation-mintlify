Usa esta guía cuando quieras abrir una conversación con una plantilla específica de WhatsApp. La [referencia detallada de plantillas](/es/templates-and-parameters) explica las reglas de validación y todos los errores de plantilla documentados.

<a id="before-you-start"></a>

## Antes de comenzar

- Debes conocer el **ID o nombre** de la plantilla. `GET .../templates/{templateId}` acepta ambos.
- Confirma que la plantilla esté aprobada para la cuenta de WhatsApp Business asociada a la línea que usarás.
- Debes tener el ID de un contacto de prueba existente, el `providerChannelId` de la línea autorizada de WhatsApp y el correo de un usuario interno de Bridge. Consulta [Identificadores y conceptos](/es/guides/identifiers).
- Revisa la secuencia de plantillas de inicio del espacio de trabajo: según su configuración, tu reemplazo puede sustituir toda la secuencia o solo la primera plantilla.

<Warning>
  La solicitud final inicia una conversación y puede enviar plantillas de inicio. Usa un contacto de prueba autorizado y el contenido previsto.
</Warning>

<a id="1-discover-the-variables"></a>

## 1. Consulta las variables

```http
GET /bridge/api/v1/workspaces/{workspaceId}/templates/{templateId}
x-api-key: YOUR_API_KEY
```

Codifica para URL el ID o nombre proporcionado. Lee `id`, `name`, `variables` y `driftWarning` en la respuesta.

| Variable | Qué hacer |
| --- | --- |
| `callerMustSupply: true` | Proporciona una cadena que no esté en blanco bajo la `key` de esa variable. |
| `callerMustSupply: false`, no personalizada | Omítela para conservar el valor que Bridge obtiene para cada contacto. Un valor enviado reemplaza ese valor para todos los contactos. |
| `isCustom: true` | Proporciona tu valor, omítelo o envíalo en blanco para usar su `default`. |

Usa la `key` independiente del proveedor, nunca el `label` visible, una posición de Meta ni un nombre de variable inventado. `driftWarning` es informativo y por sí solo no bloquea el envío.

<a id="2-prepare-your-values"></a>

## 2. Prepara los valores

Crea en tu servidor un archivo JSON que contenga únicamente claves devueltas por la consulta. Si la plantilla realmente declara `order_number` y `delivery_date`, podría contener lo siguiente:

```json
{
  "order_number": "A-10492",
  "delivery_date": "October 3"
}
```

Esos dos nombres son ejemplos, no campos universales de Bridge. Consulta tu propia plantilla antes de usarlos. Respeta las [reglas de valores de WhatsApp](/es/templates-and-parameters#whatsapp-value-rules); omite los valores no personalizados que quieras que Bridge complete, en lugar de enviar cadenas en blanco.

<a id="3-discover-check-and-create-the-conversation"></a>

## 3. Consulta, comprueba y crea la conversación

Usa Node.js con `fetch` integrado. Guarda el ejemplo como `send-template.mjs` y configura `BRIDGE_API_KEY`, `BRIDGE_WORKSPACE_ID`, `BRIDGE_TEMPLATE_ID_OR_NAME`, `TEMPLATE_VALUES_PATH`, `BRIDGE_CONTACT_ID`, `BRIDGE_PROVIDER_CHANNEL_ID` y `BRIDGE_USER_EMAIL`.

```javascript
import { readFile } from "node:fs/promises";

const BASE = "https://api-connect-us.bridge.new";
function required(name) {
  const value = process.env[name];
  if (!value) throw new Error(`Set ${name} before running this example.`);
  return value;
}
const apiKey = required("BRIDGE_API_KEY");
const workspaceId = required("BRIDGE_WORKSPACE_ID");
const templateRef = required("BRIDGE_TEMPLATE_ID_OR_NAME");
const contactId = required("BRIDGE_CONTACT_ID");
const providerChannelId = required("BRIDGE_PROVIDER_CHANNEL_ID");
const internalEmail = required("BRIDGE_USER_EMAIL");
const parameters = JSON.parse(await readFile(required("TEMPLATE_VALUES_PATH"), "utf8"));
if (parameters === null || Array.isArray(parameters) || typeof parameters !== "object") {
  throw new Error("The template values file must contain a JSON object.");
}
if (Object.entries(parameters).some(([key, value]) =>
  Array.from(key).length > 128 || typeof value !== "string" || Array.from(value).length > 1024
)) {
  throw new Error("Parameter keys and values must respect the published string limits.");
}
if (Object.keys(parameters).length > 50) throw new Error("At most 50 parameters are allowed.");
const workspacePath = `/bridge/api/v1/workspaces/${encodeURIComponent(workspaceId)}`;

async function request(method, path, body, expectedStatus) {
  const response = await fetch(`${BASE}${workspacePath}${path}`, {
    method,
    headers: {
      "x-api-key": apiKey,
      ...(body === undefined ? {} : { "Content-Type": "application/json" }),
    },
    ...(body === undefined ? {} : { body: JSON.stringify(body) }),
  });
  const result = await response.json().catch(() => null);
  if (response.status !== expectedStatus) {
    const code = result?.code ? ` (${result.code})` : "";
    throw new Error(`${method} ${path}: HTTP ${response.status}${code}`);
  }
  return result;
}

const template = await request(
  "GET", `/templates/${encodeURIComponent(templateRef)}`, undefined, 200,
);
if (!template?.id) throw new Error("Template discovery returned no id.");
const variables = template.variables ?? [];
const known = new Set(variables.map((variable) => variable.key));
const unknown = Object.keys(parameters).filter((key) => !known.has(key));
const missing = variables.filter((variable) =>
  variable.callerMustSupply &&
  (typeof parameters[variable.key] !== "string" || !parameters[variable.key].trim())
);
if (unknown.length || missing.length) {
  throw new Error(`Check template keys: ${unknown.length} unknown, ${missing.length} missing.`);
}

const conversation = await request("POST", "/conversations", {
  participants: {
    externals: [{
      identifier: contactId,
      identifierType: "ID",
      messageProviderType: "WHATSAPP",
      providerChannelId,
    }],
    internals: [{ identifier: internalEmail, identifierType: "EMAIL" }],
  },
  onboardingTemplates: [{ templateId: template.id, parameters }],
}, 201);
if (!conversation?.id || conversation.workspaceId !== workspaceId) {
  throw new Error("The Conversation response does not identify the intended workspace.");
}
console.log({ templateId: template.id, conversationId: conversation.id });
```

```bash
node send-template.mjs
```

El ejemplo usa el ID devuelto por la consulta en `onboardingTemplates[].templateId`. Las dos operaciones de conversaciones salientes también aceptan el ID o nombre de una plantilla; si envías ambos, el ID tiene prioridad. Sus cuerpos de solicitud son distintos de `onboardingTemplates`: lee el contrato de la operación antes de reutilizar este cuerpo en otra.

Las comprobaciones locales detectan claves desconocidas o faltantes. Bridge realiza igualmente su propia validación, incluida la aprobación para la línea elegida y las reglas finales de valores de WhatsApp. La validación local no equivale a aprobación ni garantiza la entrega.

<a id="recover-from-a-rejected-request"></a>

## Cómo corregir una solicitud rechazada

| Error | Qué hacer |
| --- | --- |
| Consulta `BRIDGE_TEMPLATE_0001` | Comprueba el ID o nombre y el espacio de trabajo. Esta respuesta no revela si el identificador pertenece a otro espacio de trabajo. |
| `BRIDGE_CONVERSATION_0604` | Proporciona valores que no estén en blanco para las variables de `extra.missingVariables`. |
| `BRIDGE_CONVERSATION_0605` | Quita las claves de `extra.unknownKeys`; usa las claves independientes del proveedor devueltas por la consulta. |
| `BRIDGE_CONVERSATION_0607` | Corrige los valores de `extra.invalidVariables` según su `reason`. |
| `BRIDGE_CONVERSATION_0608` | Pídele a un administrador que cambie la secuencia de plantillas de inicio del espacio de trabajo. Cambiar los valores de tu plantilla no resuelve este error de configuración. |

Consulta la [referencia completa de errores de plantillas](/es/templates-and-parameters#errors) para los errores de aprobación, pertenencia, parámetros no admitidos y solicitudes mal formadas. No reintentes automáticamente una solicitud de conversación que agotó el tiempo de espera: primero determina su resultado.

<a id="send-a-template-into-an-existing-conversation"></a>

## Envía una plantilla a una conversación existente

Usa `POST .../conversations/{conversationId}/send-template` para enviar una plantilla de proveedor a una conversación que ya existe, por ejemplo una actualización de pedido a un contacto con el que ya hablas. Bridge escribe un mensaje, que leen todos los contactos de WhatsApp de la conversación. El remitente es el sistema, no un Usuario de Bridge.

| Qué quieres hacer | Qué usar |
| --- | --- |
| Iniciar una conversación, o recuperar una liberada, y abrirla con una plantilla | `POST .../conversations` con `onboardingTemplates`, como en los pasos 1 a 3 |
| Enviar una plantilla a una conversación que ya está abierta | `POST .../conversations/{conversationId}/send-template` |

`send-template` nunca inicia ni recupera una conversación.

### Antes de enviar

- La conversación está abierta. Se rechaza una conversación liberada o bloqueada, una eliminada o una que atiende un Agente. `GET .../conversations/{conversationId}` devuelve su `status`.
- La conversación tiene al menos un contacto de WhatsApp y ya envió su plantilla inicial.
- La plantilla es una plantilla de proveedor de tu workspace, aprobada para la línea de la conversación en el idioma en que Bridge la envía a cada contacto. Consulta sus variables como en el paso 1.
- Tienes una `Idempotency-Key` para este envío.

### Envíala

```http
POST /bridge/api/v1/workspaces/{workspaceId}/conversations/{conversationId}/send-template
x-api-key: YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: erp-order-981-shipped
```

```json
{
  "template": {
    "id": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
    "parameters": {
      "order_number": "A-10492",
      "delivery_date": "October 3"
    }
  }
}
```

Envía `template.id`, o `template.name` si no tienes el id. Cuando `id` está presente es la única búsqueda: un `id` desconocido falla con `404` aunque `name` coincida con una plantilla. `parameters` sigue las reglas de los pasos 1 y 2. Una plantilla cuyo encabezado es una imagen o un video envía ese archivo.

Para enviar tu propia imagen o video como encabezado de la plantilla (la imagen o el video que se muestra en la parte superior del mensaje), envía `template.media` con su `type` (`IMAGE`, `VIDEO` o `GIF`, el tipo del encabezado) y una fuente. Envía el `mediaId` de un archivo que subiste con `POST /bridge/api/v1/workspaces/{workspaceId}/files`, como en [Enviar PDF y otros adjuntos](/es/guides/send-attachments):

```json
{
  "template": {
    "id": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
    "parameters": {
      "order_number": "A-10492"
    },
    "media": {
      "type": "IMAGE",
      "mediaId": "9b2f6a52-1f3c-4a53-8f58-3c6a2e7d1b10"
    }
  }
}
```

O envía una `url` `https` pública del archivo:

```json
{
  "template": {
    "id": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
    "parameters": {
      "order_number": "A-10492"
    },
    "media": {
      "type": "IMAGE",
      "url": "https://cdn.example.com/promo/spring-sale.png"
    }
  }
}
```

`type` es obligatorio, y envías `mediaId` o `url`, nunca ambos. `type` debe ser el tipo del encabezado de la plantilla; si no, la solicitud falla con `BRIDGE_TEMPLATE_0012`. Con `mediaId`, el archivo subido también debe tener ese tipo, pertenecer a tu workspace y tener su carga terminada. Con `url`, Bridge descarga el archivo después de responder `201`, y una descarga que falla no se informa en esta respuesta. Una plantilla con encabezado de imagen o de video que no tiene un archivo configurado necesita `media`. Dos solicitudes tienen el mismo cuerpo solo si también envían el mismo `type` y el mismo `mediaId` o `url`. WhatsApp aún puede rechazar, después del `201`, un archivo que supere los límites de encabezado.

Una solicitud correcta responde `201`:

```json
{
  "conversationId": "7d4a1f2e-3b5c-4d6e-8f9a-0b1c2d3e4f5a",
  "messageId": "b6cf1c4a-2b1e-4e63-8f3e-0f9d1a2a1234",
  "templateId": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
  "templateName": "order_shipped_promo"
}
```

Conserva `messageId`. `201` significa que Bridge guardó el mensaje para enviarlo; [Respuestas y reintentos](/es/guides/responses) explica qué no te dice.

### Reintenta con la misma clave

`Idempotency-Key` es obligatoria, de 1 a 255 caracteres, y Bridge la conserva 24 horas. Usa una clave nueva para cada envío y reutilízala solo para reintentar ese envío. Dos solicitudes tienen el mismo cuerpo cuando nombran la misma plantilla y los mismos `parameters`: un `parameters` ausente y `{}` son lo mismo, y `name` no influye cuando `id` está presente.

| Situación | Resultado | Qué hacer |
| --- | --- | --- |
| Misma clave, mismo cuerpo | `201` con el primer mensaje y `Idempotent-Replayed: true` | No se envió nada dos veces. Conserva `messageId`. |
| Misma clave, cuerpo distinto | `422` `BRIDGE_CORE_1202` | Usa una clave nueva para el cuerpo nuevo. |
| Misma clave mientras la primera solicitud sigue en curso | `409` `BRIDGE_CORE_1201` | Reintenta con la misma clave después de una pausa. |
| La primera solicitud falló antes de guardar nada | Bridge libera la clave | Corrige la causa y reintenta con la misma clave. |
| La primera solicitud se interrumpió después de guardar el mensaje | `409` `BRIDGE_CORE_1201` hasta por 24 horas | El mensaje puede existir. La API no tiene una operación para listar mensajes: pídele a un Usuario de Bridge que revise la conversación antes de enviar de nuevo con una clave nueva. |

### Si se rechaza la solicitud

| Error | Qué hacer |
| --- | --- |
| `BRIDGE_CONVERSATION_0007` | La conversación fue liberada. Vuelve a iniciarla con `POST .../conversations`. |
| `BRIDGE_CONVERSATION_0011` | Un Agente está atendiendo la conversación. Consúltala con `GET .../conversations/{conversationId}` y reintenta cuando su `status` sea `ACTIVE`. |
| `BRIDGE_CONVERSATION_0004` | La conversación no está activa. Reintenta solo cuando su `status` sea `ACTIVE`. |
| `BRIDGE_CONVERSATION_0613` | La plantilla inicial aún se está enviando. Reintenta en unos segundos. |
| `BRIDGE_COMMERCIAL_CONSENT_0203` | Un contacto no acepta mensajes que inicia Bridge. La [referencia de errores](/es/error-codes#commercial-consent-error-codes) explica cuándo ocurre. |
| `BRIDGE_TEMPLATE_0006`, `0007`, `0009`, `0010` | Corrige la plantilla o sus valores. La [referencia de errores](/es/error-codes#template-error-codes) describe cada uno. |
| `BRIDGE_TEMPLATE_0011`, `0012`, `0013` | Corrige `template.media`: envíalo solo para una plantilla con encabezado de imagen o de video, con un `type` que coincida. La [referencia de errores](/es/error-codes#template-error-codes) describe cada uno. |
| `BRIDGE_PRELOAD_FILE_0001`, `0002` | El `mediaId` no es un archivo de tu workspace, o su carga no ha terminado. Consulta [Enviar PDF y otros adjuntos](/es/guides/send-attachments). |

Una solicitud rechazada con uno de estos códigos no envió nada. Todos los códigos, incluidos `BRIDGE_TEMPLATE_0001`, `BRIDGE_CONVERSATION_0001` y `BRIDGE_CONVERSATION_0201`, están en [Códigos de error](/es/error-codes).
