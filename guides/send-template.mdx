Use this recipe when you want a Conversation to open with a particular WhatsApp template. The detailed [template reference](/templates-and-parameters) explains validation rules and every documented template error.

## Before you start

- Know the template's **ID or name**. Both are accepted by `GET .../templates/{templateId}`.
- Confirm the template is approved for the WhatsApp Business Account behind the intended line.
- Have an existing test Contact ID, the authorized WhatsApp `providerChannelId`, and an internal Bridge User's email. See [Identifiers and concepts](/guides/identifiers).
- Review the workspace's onboarding sequence: your override can replace the whole sequence or only its first template, depending on workspace configuration.

<Warning>
  The final request starts a Conversation and can send onboarding templates. Use an authorized test Contact and intended content.
</Warning>

## 1. Discover the variables

```http
GET /bridge/api/v1/workspaces/{workspaceId}/templates/{templateId}
x-api-key: YOUR_API_KEY
```

URL-encode the supplied ID or name. Read the response's `id`, `name`, `variables`, and `driftWarning`.

| Variable | Action |
| --- | --- |
| `callerMustSupply: true` | Supply a non-blank string under that variable's `key`. |
| `callerMustSupply: false`, not custom | Omit it to keep Bridge's per-Contact value. A supplied value replaces that value for every Contact. |
| `isCustom: true` | Supply your value, or omit it or send it blank to use its `default`. |

Use the agnostic `key`, never the display `label`, a Meta position, or an invented variable name. `driftWarning` is diagnostic and does not by itself block sending.

## 2. Prepare your values

Create a server-side JSON file containing only keys returned by discovery. For a template that actually declares `order_number` and `delivery_date`, it could contain:

```json
{
  "order_number": "A-10492",
  "delivery_date": "October 3"
}
```

Those two names are examples, not universal Bridge fields. Read your own template before using them. Keep values within the [WhatsApp value rules](/templates-and-parameters#whatsapp-value-rules); omit non-custom values you want Bridge to fill instead of sending blank strings.

## 3. Discover, check, and create the Conversation

Use Node.js with built-in `fetch`. Save this as `send-template.mjs` and set `BRIDGE_API_KEY`, `BRIDGE_WORKSPACE_ID`, `BRIDGE_TEMPLATE_ID_OR_NAME`, `TEMPLATE_VALUES_PATH`, `BRIDGE_CONTACT_ID`, `BRIDGE_PROVIDER_CHANNEL_ID`, and `BRIDGE_USER_EMAIL`.

```javascript
import { readFile } from "node:fs/promises";

const BASE = "https://api-connect-us.bridge.new";
function required(name) {
  const value = process.env[name];
  if (!value) throw new Error(`Set ${name} before running this example.`);
  return value;
}
const apiKey = required("BRIDGE_API_KEY");
const workspaceId = required("BRIDGE_WORKSPACE_ID");
const templateRef = required("BRIDGE_TEMPLATE_ID_OR_NAME");
const contactId = required("BRIDGE_CONTACT_ID");
const providerChannelId = required("BRIDGE_PROVIDER_CHANNEL_ID");
const internalEmail = required("BRIDGE_USER_EMAIL");
const parameters = JSON.parse(await readFile(required("TEMPLATE_VALUES_PATH"), "utf8"));
if (parameters === null || Array.isArray(parameters) || typeof parameters !== "object") {
  throw new Error("The template values file must contain a JSON object.");
}
if (Object.entries(parameters).some(([key, value]) =>
  Array.from(key).length > 128 || typeof value !== "string" || Array.from(value).length > 1024
)) {
  throw new Error("Parameter keys and values must respect the published string limits.");
}
if (Object.keys(parameters).length > 50) throw new Error("At most 50 parameters are allowed.");
const workspacePath = `/bridge/api/v1/workspaces/${encodeURIComponent(workspaceId)}`;

async function request(method, path, body, expectedStatus) {
  const response = await fetch(`${BASE}${workspacePath}${path}`, {
    method,
    headers: {
      "x-api-key": apiKey,
      ...(body === undefined ? {} : { "Content-Type": "application/json" }),
    },
    ...(body === undefined ? {} : { body: JSON.stringify(body) }),
  });
  const result = await response.json().catch(() => null);
  if (response.status !== expectedStatus) {
    const code = result?.code ? ` (${result.code})` : "";
    throw new Error(`${method} ${path}: HTTP ${response.status}${code}`);
  }
  return result;
}

const template = await request(
  "GET", `/templates/${encodeURIComponent(templateRef)}`, undefined, 200,
);
if (!template?.id) throw new Error("Template discovery returned no id.");
const variables = template.variables ?? [];
const known = new Set(variables.map((variable) => variable.key));
const unknown = Object.keys(parameters).filter((key) => !known.has(key));
const missing = variables.filter((variable) =>
  variable.callerMustSupply &&
  (typeof parameters[variable.key] !== "string" || !parameters[variable.key].trim())
);
if (unknown.length || missing.length) {
  throw new Error(`Check template keys: ${unknown.length} unknown, ${missing.length} missing.`);
}

const conversation = await request("POST", "/conversations", {
  participants: {
    externals: [{
      identifier: contactId,
      identifierType: "ID",
      messageProviderType: "WHATSAPP",
      providerChannelId,
    }],
    internals: [{ identifier: internalEmail, identifierType: "EMAIL" }],
  },
  onboardingTemplates: [{ templateId: template.id, parameters }],
}, 201);
if (!conversation?.id || conversation.workspaceId !== workspaceId) {
  throw new Error("The Conversation response does not identify the intended workspace.");
}
console.log({ templateId: template.id, conversationId: conversation.id });
```

```bash
node send-template.mjs
```

The example uses the ID returned by discovery in `onboardingTemplates[].templateId`. `POST .../conversations/{conversationId}/send-template` takes only a template ID. The LeadScout outbound operation also accepts a template name, with the ID taking precedence when both are supplied. Their request shapes differ from `onboardingTemplates`; read the operation's contract before reusing this body elsewhere.

The local checks catch unknown and missing keys. Bridge still performs its own validation, including approval for the selected line and the final WhatsApp value rules. Do not treat local validation as approval or a delivery guarantee.

## Recover from a rejected request

| Error | What to do |
| --- | --- |
| Discovery `BRIDGE_TEMPLATE_0001` | Check the ID/name and workspace. This response does not reveal whether another workspace owns that identifier. |
| `BRIDGE_CONVERSATION_0604` | Supply the non-blank values listed in `extra.missingVariables`. |
| `BRIDGE_CONVERSATION_0605` | Remove keys listed in `extra.unknownKeys`; use discovery's agnostic keys. |
| `BRIDGE_CONVERSATION_0607` | Correct the values listed in `extra.invalidVariables` according to their `reason`. |
| `BRIDGE_CONVERSATION_0608` | Ask a workspace administrator to change the configured onboarding sequence. Changing your template values does not fix this configuration error. |

Read the [complete template error reference](/templates-and-parameters#errors) for approval, ownership, unsupported parameters, and malformed requests. Do not retry a timed-out Conversation request automatically: determine its outcome first.

## Send a template into an existing Conversation

Use `POST .../conversations/{conversationId}/send-template` to send one provider template into a Conversation that already exists, such as an order update to a Contact you already talk to. Bridge writes one Message, read by every WhatsApp Contact of the Conversation. The sender is the system, not a Bridge User.

| You want to | Use |
| --- | --- |
| Start a Conversation, or recover a released one, and open it with a template | `POST .../conversations` with `onboardingTemplates`, as in steps 1 to 3 |
| Send a template into a Conversation that is already open | `POST .../conversations/{conversationId}/send-template` |

`send-template` never starts or recovers a Conversation.

### Before you send

- The Conversation is open. A released or blocked Conversation, a deleted one, or one an Agent is handling is refused. `GET .../conversations/{conversationId}` returns its `status`.
- The Conversation has at least one WhatsApp Contact. Its opening template has been sent, or the template you send is a marketing or utility template, which becomes the opening template (see below).
- The template is a provider template of your workspace, approved for the line of every WhatsApp Contact of the Conversation, in the language Bridge sends to that Contact. Discover its variables as in step 1.
- You have an `Idempotency-Key` for this send.

### Send it

```http
POST /bridge/api/v1/workspaces/{workspaceId}/conversations/{conversationId}/send-template
x-api-key: YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: erp-order-981-shipped
```

```json
{
  "template": {
    "id": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
    "parameters": {
      "order_number": "A-10492",
      "delivery_date": "October 3"
    }
  }
}
```

Send `template.id`, the `id` that step 1 returns: `GET .../templates/{templateId}` accepts the template's name and answers with its `id`. The request takes no `template.name`: a body with `name` fails with `422`. An unknown `id` fails with `404`. `parameters` follows the rules of steps 1 and 2. A template whose header is an image or video sends that file.

To send your own image or video as the template's header (the image or video shown at the top of the message) instead, send `template.media` with its `type` (`IMAGE`, `VIDEO` or `GIF`, the type of the header) and one source. Send the `mediaId` of a file you uploaded with `POST /bridge/api/v1/workspaces/{workspaceId}/files`, as in [Send PDFs and other attachments](/guides/send-attachments):

```json
{
  "template": {
    "id": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
    "parameters": {
      "order_number": "A-10492"
    },
    "media": {
      "type": "IMAGE",
      "mediaId": "9b2f6a52-1f3c-4a53-8f58-3c6a2e7d1b10"
    }
  }
}
```

Or send a public `https` `url` of the file:

```json
{
  "template": {
    "id": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
    "parameters": {
      "order_number": "A-10492"
    },
    "media": {
      "type": "IMAGE",
      "url": "https://cdn.example.com/promo/spring-sale.png"
    }
  }
}
```

`type` is required, and you send `mediaId` or `url`, never both. `type` must be the type of the template's header, or the request fails with `BRIDGE_TEMPLATE_0012`; with `mediaId`, the uploaded file must have that type too, and it must belong to your workspace with its upload finished. With `url`, Bridge downloads the file asynchronously: the result of the download is not part of the `201` response, and a download that fails is not reported in it. A template with an image or video header and no file configured on it needs `media`. Two requests have the same body only when they also send the same `type` and the same `mediaId` or `url`. WhatsApp can still refuse a file larger than its header limits after the `201`.

A successful request answers `201`:

```json
{
  "conversationId": "7d4a1f2e-3b5c-4d6e-8f9a-0b1c2d3e4f5a",
  "messageId": "b6cf1c4a-2b1e-4e63-8f3e-0f9d1a2a1234",
  "templateId": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
  "templateName": "order_shipped_promo"
}
```

Retain `messageId`. `201` means Bridge stored the Message for sending; [Responses and retries](/guides/responses) explains what it does not tell you.

### The opening template and the promotional cooldown

A Conversation can have no opening template yet, for example one started by email. A marketing or utility template sent into it becomes its opening template, and the Conversation then accepts any template. Until then, a template of another category is refused with `BRIDGE_CONVERSATION_0609`. If two requests try to open the same Conversation at once, one of them is refused with `BRIDGE_CONVERSATION_0613`: retry it in a few seconds.

A marketing or utility template is also subject to the workspace's promotional cooldown, the same setting that throttles these sends in Bridge. If any Contact of the Conversation received one inside that period, the request fails with `BRIDGE_CONVERSATION_0406` and sends nothing to any Contact: `extra.contactIds` lists those Contacts and `extra.retryAfterSeconds` is the longest wait left. Each successful send is recorded for every Contact, so it counts toward the cooldown like a send from the Bridge app.

### Retry with the same key

`Idempotency-Key` is required, 1 to 255 characters, and Bridge keeps it for 24 hours. Use a new key for each send and reuse it only to retry that send. Two requests are the same send when they have the same `conversationId`, have the same `template.id` and carry the same `parameters` and `media`: an absent `parameters` and `{}` are the same.

| Situation | Result | What to do |
| --- | --- | --- |
| The `Idempotency-Key` HTTP header is missing, empty or longer than 255 characters | `422`, with the field in `errors[]` | Send a valid key. |
| Same key, same send | `201` with the first Message and `Idempotent-Replayed: true` | Nothing was sent twice. Keep `messageId`. |
| Same key, different send, such as another body or another Conversation | `422` `BRIDGE_CORE_1202` | Use a new key for the new send. |
| Same key while the first request is still running | `409` `BRIDGE_CORE_1201` | Retry with the same key after a pause. |
| The first request failed before it stored anything | Bridge frees the key | Fix the cause and retry with the same key. |
| The first request was cut off after it stored the Message | `409` `BRIDGE_CORE_1201` for up to 24 hours | The Message may exist. The API has no operation to list Messages, so ask a Bridge User to check the Conversation before you send again with a new key. |

### If the request is rejected

| Error | What to do |
| --- | --- |
| `BRIDGE_TEMPLATE_0001` | No provider template of your workspace has that `id`. Send the `id` of a provider template of your workspace. |
| `BRIDGE_CONVERSATION_0001` | The Conversation does not exist in your workspace. Send the `conversationId` of one of your Conversations. |
| `BRIDGE_CONVERSATION_0007` | The Conversation was released. Start it again with `POST .../conversations`, requesting the same Contacts and lines. |
| `BRIDGE_CONVERSATION_0011` | An Agent is handling the Conversation. Check it with `GET .../conversations/{conversationId}` and retry when its `status` is `ACTIVE`. |
| `BRIDGE_CONVERSATION_0004` | The Conversation is not active. Retry only when its `status` is `ACTIVE`. |
| `BRIDGE_CONVERSATION_0609` | The Conversation has no opening template yet and this template is not a marketing or utility template. Send a marketing or utility template: it becomes the opening template. |
| `BRIDGE_CONVERSATION_0613` | Another request is sending the Conversation's opening template, or that template is still being sent. Retry in a few seconds: the block lasts at most 120 seconds after the opening template was created. |
| `BRIDGE_CONVERSATION_0201` | The Conversation has no WhatsApp Contact. Send into a Conversation that has one: `GET .../conversations/{conversationId}` lists its participants. |
| `BRIDGE_COMMERCIAL_CONSENT_0203` | A Contact does not accept messages Bridge starts. Do not retry: stop sending templates into this Conversation until the Contact accepts messages again. The [error reference](/error-codes#commercial-consent-error-codes) says when it happens. |
| `BRIDGE_CONVERSATION_0406` | The template is a marketing or utility template and a Contact of the Conversation already received one inside the workspace's promotional cooldown. `extra.contactIds` lists those Contacts and `extra.retryAfterSeconds` is the longest wait left. Nothing was sent to any Contact. Retry after `retryAfterSeconds` seconds. |
| `BRIDGE_TEMPLATE_0006` | The template is not approved for the line and language of at least one WhatsApp Contact, or a Contact's line has no WhatsApp Business account. Use a template approved for the line and language of every Contact of the Conversation. |
| `BRIDGE_TEMPLATE_0007`, `0009`, `0010` | Fix the template values. The [error reference](/error-codes#template-error-codes) lists each one. |
| `BRIDGE_TEMPLATE_0011`, `0012` | Fix `template.media`: send it only for a template with an image or video header, with a `type` that matches it, and with `mediaId` a file of that type. The [error reference](/error-codes#template-error-codes) lists each one. |
| `BRIDGE_TEMPLATE_0013` | The template has an image or video header and no file to send. Send `template.media`, or ask for a file to be configured on the template. When `extra.expectedType` is `DOCUMENT`, Bridge cannot send document headers, with or without `template.media`: use another template. |
| `BRIDGE_PRELOAD_FILE_0001` | The `mediaId` is not a file of your workspace. Upload the file as in [Send PDFs and other attachments](/guides/send-attachments) and send the `mediaId` it returns. |
| `BRIDGE_PRELOAD_FILE_0002` | The file is not usable yet. If it is still uploading, finish the upload and retry with the same `mediaId`. If its upload was cancelled, upload a new file and send the new `mediaId`. |

A request with several problems is answered with the first one Bridge finds: fix that error and send again, since another may follow. A request rejected with one of these codes sent nothing. Every code is in [Error codes](/error-codes).
