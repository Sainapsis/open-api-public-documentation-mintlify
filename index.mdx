## Make your first REST API request

<Steps>
  <Step title="Get your API credentials" icon="shield-keyhole">
    Follow [Authentication](/credentials) to generate an API key in the Bridge Admin Console. Ask your Bridge administrator for access if needed. Keep the key on your server.
  </Step>
  <Step title="Check the connection" icon="code">
    Use your `x-api-key` header to call the authenticated [health check](/api-reference/health/health-check) at `https://api-connect-us.bridge.new/bridge/api/health`.

    Continue in the **REST API** tab. Each endpoint lists its fields, responses, and examples.
  </Step>
</Steps>

<Note>
  Custom Connections uses a separate endpoint and public `captureKey`. Follow its [integration guide](/lead-capture/integration). A `202` confirms acceptance, not WhatsApp delivery.
</Note>

## Build from the published contract

- [Create a Contact and send a message](/guides/first-conversation) — follow the complete Contact → conversation → message workflow.
- [Send a PDF or attachment](/guides/send-attachments) — checksum, upload URL, file upload and message.
- [Send a WhatsApp template](/guides/send-template) — discover variables and supply caller-required values.
- [Start Agent outbound and hand off](/guides/agent-outbound) — choose an Agent, understand `forceSend`, reuse and recovery.
- [Look up identifiers](/guides/identifiers) and [page through results](/guides/pagination) — use the right IDs and cursors.
- [Rate limits](/rate-limits) — share the request budget and handle `429` responses.
- [Error codes](/error-codes) — interpret REST API errors. Custom Connections has a separate [error reference](/lead-capture/errors).
- [WhatsApp template parameters](/templates-and-parameters) — open conversations with WhatsApp templates and supply their variables.
- [Changelog](/changelog) — review changes that affect integrations.
