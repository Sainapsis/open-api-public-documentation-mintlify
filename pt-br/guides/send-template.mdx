Use este guia quando quiser abrir uma conversa com um template específico de WhatsApp. A [referência detalhada de templates](/pt-br/templates-and-parameters) explica as regras de validação e todos os erros de template documentados.

<a id="before-you-start"></a>

## Antes de começar

- Tenha o **ID ou nome** do template. Ambos são aceitos por `GET .../templates/{templateId}`.
- Confirme que o template foi aprovado para a conta WhatsApp Business associada à linha desejada.
- Tenha o ID de um Contato de teste existente, o `providerChannelId` da linha autorizada de WhatsApp e o e-mail de um usuário interno do Bridge. Veja [conceitos e identificadores](/pt-br/guides/identifiers).
- Revise a sequência inicial do workspace: sua substituição pode trocar toda a sequência ou apenas o primeiro template, conforme a configuração.

<Warning>
  A requisição final inicia uma conversa e pode enviar os templates iniciais. Use um Contato de teste autorizado e o conteúdo pretendido.
</Warning>

<a id="1-discover-the-variables"></a>

## 1. Descubra as variáveis

```http
GET /bridge/api/v1/workspaces/{workspaceId}/templates/{templateId}
x-api-key: YOUR_API_KEY
```

Codifique o ID ou nome fornecido para uso na URL. Leia `id`, `name`, `variables` e `driftWarning` na resposta.

| Variável | Ação |
| --- | --- |
| `callerMustSupply: true` | Forneça uma string não vazia na `key` dessa variável. |
| `callerMustSupply: false`, não personalizada | Omita-a para manter o valor definido pelo Bridge para cada Contato. Um valor informado substitui esse valor para todos os Contatos. |
| `isCustom: true` | Forneça seu valor ou omita-o ou envie-o vazio para usar o `default`. |

Use a `key` agnóstica, nunca o `label` de exibição, uma posição da Meta ou um nome de variável inventado. `driftWarning` é diagnóstico e, por si só, não bloqueia o envio.

<a id="2-prepare-your-values"></a>

## 2. Prepare seus valores

Crie um arquivo JSON no servidor contendo somente as chaves retornadas pela descoberta. Para um template que realmente declare `order_number` e `delivery_date`, ele poderia conter:

```json
{
  "order_number": "A-10492",
  "delivery_date": "October 3"
}
```

Esses dois nomes são exemplos, não campos universais do Bridge. Consulte seu próprio template antes de usá-los. Mantenha os valores dentro das [regras de valores do WhatsApp](/pt-br/templates-and-parameters#whatsapp-value-rules). Para valores não personalizados que você quer que o Bridge preencha, omita as chaves em vez de enviar strings vazias.

<a id="3-discover-check-and-create-the-conversation"></a>

## 3. Descubra, valide e crie a conversa

Use Node.js com `fetch` nativo. Salve como `send-template.mjs` e defina `BRIDGE_API_KEY`, `BRIDGE_WORKSPACE_ID`, `BRIDGE_TEMPLATE_ID_OR_NAME`, `TEMPLATE_VALUES_PATH`, `BRIDGE_CONTACT_ID`, `BRIDGE_PROVIDER_CHANNEL_ID` e `BRIDGE_USER_EMAIL`.

```javascript
import { readFile } from "node:fs/promises";

const BASE = "https://api-connect-us.bridge.new";
function required(name) {
  const value = process.env[name];
  if (!value) throw new Error(`Set ${name} before running this example.`);
  return value;
}
const apiKey = required("BRIDGE_API_KEY");
const workspaceId = required("BRIDGE_WORKSPACE_ID");
const templateRef = required("BRIDGE_TEMPLATE_ID_OR_NAME");
const contactId = required("BRIDGE_CONTACT_ID");
const providerChannelId = required("BRIDGE_PROVIDER_CHANNEL_ID");
const internalEmail = required("BRIDGE_USER_EMAIL");
const parameters = JSON.parse(await readFile(required("TEMPLATE_VALUES_PATH"), "utf8"));
if (parameters === null || Array.isArray(parameters) || typeof parameters !== "object") {
  throw new Error("The template values file must contain a JSON object.");
}
if (Object.entries(parameters).some(([key, value]) =>
  Array.from(key).length > 128 || typeof value !== "string" || Array.from(value).length > 1024
)) {
  throw new Error("Parameter keys and values must respect the published string limits.");
}
if (Object.keys(parameters).length > 50) throw new Error("At most 50 parameters are allowed.");
const workspacePath = `/bridge/api/v1/workspaces/${encodeURIComponent(workspaceId)}`;

async function request(method, path, body, expectedStatus) {
  const response = await fetch(`${BASE}${workspacePath}${path}`, {
    method,
    headers: {
      "x-api-key": apiKey,
      ...(body === undefined ? {} : { "Content-Type": "application/json" }),
    },
    ...(body === undefined ? {} : { body: JSON.stringify(body) }),
  });
  const result = await response.json().catch(() => null);
  if (response.status !== expectedStatus) {
    const code = result?.code ? ` (${result.code})` : "";
    throw new Error(`${method} ${path}: HTTP ${response.status}${code}`);
  }
  return result;
}

const template = await request(
  "GET", `/templates/${encodeURIComponent(templateRef)}`, undefined, 200,
);
if (!template?.id) throw new Error("Template discovery returned no id.");
const variables = template.variables ?? [];
const known = new Set(variables.map((variable) => variable.key));
const unknown = Object.keys(parameters).filter((key) => !known.has(key));
const missing = variables.filter((variable) =>
  variable.callerMustSupply &&
  (typeof parameters[variable.key] !== "string" || !parameters[variable.key].trim())
);
if (unknown.length || missing.length) {
  throw new Error(`Check template keys: ${unknown.length} unknown, ${missing.length} missing.`);
}

const conversation = await request("POST", "/conversations", {
  participants: {
    externals: [{
      identifier: contactId,
      identifierType: "ID",
      messageProviderType: "WHATSAPP",
      providerChannelId,
    }],
    internals: [{ identifier: internalEmail, identifierType: "EMAIL" }],
  },
  onboardingTemplates: [{ templateId: template.id, parameters }],
}, 201);
if (!conversation?.id || conversation.workspaceId !== workspaceId) {
  throw new Error("The Conversation response does not identify the intended workspace.");
}
console.log({ templateId: template.id, conversationId: conversation.id });
```

```bash
node send-template.mjs
```

O exemplo usa o ID retornado pela descoberta em `onboardingTemplates[].templateId`. `POST .../conversations/{conversationId}/send-template` aceita apenas o ID do template. A operação outbound do LeadScout também aceita o nome de um template, com prioridade para o ID quando ambos são informados. Seus formatos de requisição são diferentes de `onboardingTemplates`; leia o contrato da operação antes de reutilizar esse corpo em outro contexto.

As verificações locais detectam chaves desconhecidas ou obrigatórias ausentes. O Bridge ainda realiza sua própria validação, incluindo a aprovação para a linha selecionada e as regras finais de valores do WhatsApp. Não trate a validação local como aprovação ou garantia de entrega.

<a id="recover-from-a-rejected-request"></a>

## Corrija uma requisição rejeitada

| Erro | O que fazer |
| --- | --- |
| Descoberta `BRIDGE_TEMPLATE_0001` | Confira o ID ou nome e o workspace. Essa resposta não revela se o identificador pertence a outro workspace. |
| `BRIDGE_CONVERSATION_0604` | Forneça valores não vazios para as variáveis de `extra.missingVariables`. |
| `BRIDGE_CONVERSATION_0605` | Remova as chaves de `extra.unknownKeys`; use as chaves agnósticas da descoberta. |
| `BRIDGE_CONVERSATION_0607` | Corrija os valores de `extra.invalidVariables` conforme o `reason` de cada um. |
| `BRIDGE_CONVERSATION_0608` | Peça a um administrador do workspace para alterar a sequência inicial configurada. Mudar os valores do seu template não corrige esse erro de configuração. |

Leia a [referência completa de erros de templates](/pt-br/templates-and-parameters#errors) para entender aprovação, titularidade, parâmetros não aceitos e requisições malformadas. Não repita automaticamente uma requisição de conversa que expirou: primeiro verifique o resultado.

<a id="send-a-template-into-an-existing-conversation"></a>

## Envie um template para uma conversa existente

Use `POST .../conversations/{conversationId}/send-template` para enviar um template de provedor a uma conversa que já existe, por exemplo uma atualização de pedido a um contato com quem você já conversa. O Bridge grava uma mensagem, lida por todos os contatos de WhatsApp da conversa. O remetente é o sistema, não um Usuário do Bridge.

| O que você quer fazer | O que usar |
| --- | --- |
| Iniciar uma conversa, ou recuperar uma liberada, e abri-la com um template | `POST .../conversations` com `onboardingTemplates`, como nos passos 1 a 3 |
| Enviar um template para uma conversa que já está aberta | `POST .../conversations/{conversationId}/send-template` |

`send-template` nunca inicia nem recupera uma conversa.

### Antes de enviar

- A conversa está aberta. Uma conversa liberada ou bloqueada, uma excluída ou uma atendida por um Agente é recusada. `GET .../conversations/{conversationId}` retorna o `status` dela.
- A conversa tem pelo menos um contato de WhatsApp. Ela já enviou o template inicial, ou o template que você envia é de marketing ou de utilidade e passa a ser o template inicial (veja abaixo).
- O template é um template de provedor do seu workspace, aprovado para a linha de cada contato de WhatsApp da conversa, no idioma em que o Bridge o envia a esse contato. Descubra as variáveis dele como no passo 1.
- Você tem uma `Idempotency-Key` para este envio.

### Envie

```http
POST /bridge/api/v1/workspaces/{workspaceId}/conversations/{conversationId}/send-template
x-api-key: YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: erp-order-981-shipped
```

```json
{
  "template": {
    "id": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
    "parameters": {
      "order_number": "A-10492",
      "delivery_date": "October 3"
    }
  }
}
```

Envie `template.id`, o `id` que o passo 1 retorna: `GET .../templates/{templateId}` aceita o nome do template e responde com o `id` dele. A requisição não aceita `template.name`: um corpo com `name` falha com `422`. Um `id` desconhecido falha com `404`. `parameters` segue as regras dos passos 1 e 2. Um template cujo cabeçalho é uma imagem ou um vídeo envia esse arquivo.

Para enviar sua própria imagem ou vídeo como cabeçalho do template (a imagem ou o vídeo exibido no topo da mensagem), envie `template.media` com seu `type` (`IMAGE`, `VIDEO` ou `GIF`, o tipo do cabeçalho) e uma fonte. Envie o `mediaId` de um arquivo que você enviou com `POST /bridge/api/v1/workspaces/{workspaceId}/files`, como em [Enviar PDF e outros anexos](/pt-br/guides/send-attachments):

```json
{
  "template": {
    "id": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
    "parameters": {
      "order_number": "A-10492"
    },
    "media": {
      "type": "IMAGE",
      "mediaId": "9b2f6a52-1f3c-4a53-8f58-3c6a2e7d1b10"
    }
  }
}
```

Ou envie uma `url` `https` pública do arquivo:

```json
{
  "template": {
    "id": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
    "parameters": {
      "order_number": "A-10492"
    },
    "media": {
      "type": "IMAGE",
      "url": "https://cdn.example.com/promo/spring-sale.png"
    }
  }
}
```

`type` é obrigatório, e você envia `mediaId` ou `url`, nunca os dois. `type` deve ser o tipo do cabeçalho do template; caso contrário, a requisição falha com `BRIDGE_TEMPLATE_0012`. Com `mediaId`, o arquivo enviado também deve ter esse tipo, pertencer ao seu workspace e ter o upload terminado. Com `url`, o Bridge baixa o arquivo de forma assíncrona: o resultado do download não faz parte da resposta `201`, e um download que falha não é informado nela. Um template com cabeçalho de imagem ou de vídeo que não tem arquivo configurado precisa de `media`. Duas requisições têm o mesmo corpo só se também enviarem o mesmo `type` e o mesmo `mediaId` ou `url`. O WhatsApp ainda pode recusar, depois do `201`, um arquivo que ultrapasse os limites de cabeçalho.

Uma requisição bem-sucedida responde `201`:

```json
{
  "conversationId": "7d4a1f2e-3b5c-4d6e-8f9a-0b1c2d3e4f5a",
  "messageId": "b6cf1c4a-2b1e-4e63-8f3e-0f9d1a2a1234",
  "templateId": "4061e74e-f6fe-4072-a760-3aec0b64f7a6",
  "templateName": "order_shipped_promo"
}
```

Guarde `messageId`. `201` significa que o Bridge gravou a mensagem para envio; [Respostas e novas tentativas](/pt-br/guides/responses) explica o que ele não informa.

### O template inicial e o período de espera promocional

Uma conversa pode ainda não ter template inicial, por exemplo uma iniciada por uma chamada ou por e-mail. Um template de marketing ou de utilidade enviado a ela passa a ser o template inicial. Até lá, um template de outra categoria é recusado com `BRIDGE_CONVERSATION_0609`. Se duas requisições tentam abrir ao mesmo tempo a mesma conversa pendente, só uma envia. A outra é recusada com `BRIDGE_CONVERSATION_0613`, ou com `BRIDGE_CONVERSATION_0406` quando a primeira já reservou o período de espera do contato em um workspace que o tem. Tente de novo em alguns segundos.

Quando a conversa já tem seu template inicial, qualquer template ainda passa pelas verificações habituais: o período de espera promocional (`BRIDGE_CONVERSATION_0406`), um template inicial que ainda está sendo enviado (`BRIDGE_CONVERSATION_0613`), o consentimento do contato e a aprovação do WhatsApp.

Um template de marketing ou de utilidade também está sujeito ao período de espera promocional do workspace, a mesma configuração que o Bridge aplica a esses envios no app, com seu valor padrão quando o workspace não a alterou. Se outro envio já reservou o período de espera de algum contato da conversa, a requisição falha com `BRIDGE_CONVERSATION_0406` e não envia nada a nenhum contato: `extra.contactIds` lista esses contatos e `extra.retryAfterSeconds` é a maior espera restante, também no header `Retry-After`. `BRIDGE_CONVERSATION_0406` significa que outro envio reservou o período de espera do contato, não que o WhatsApp o tenha entregue: o Bridge conta os envios que registrou ou está registrando. Cada envio bem-sucedido é registrado para cada contato, então conta para o período de espera como um envio feito pelo app do Bridge.

O Bridge reserva o período de espera de cada contato antes de gravar a mensagem, então dois envios de marketing ou de utilidade que disputam o mesmo contato não podem sair ambos: um recebe `BRIDGE_CONVERSATION_0406`.

### Tente de novo com a mesma chave

`Idempotency-Key` é obrigatória, de 1 a 255 caracteres, e o Bridge a mantém por 24 horas. Use uma chave nova para cada envio e reutilize-a apenas para repetir esse envio. Duas requisições são o mesmo envio quando têm o mesmo `conversationId`, têm o mesmo `template.id` e levam os mesmos `parameters` e `media`: um `parameters` ausente e `{}` são equivalentes.

| Situação | Resultado | O que fazer |
| --- | --- | --- |
| O header HTTP `Idempotency-Key` está ausente, vazio ou tem mais de 255 caracteres | `422`, com o campo em `errors[]` | Envie uma chave válida. |
| Mesma chave, mesmo envio | `201` com a primeira mensagem e `Idempotent-Replayed: true` | Nada foi enviado duas vezes. Guarde `messageId`. |
| Mesma chave, envio diferente, por exemplo outro corpo ou outra conversa | `422` `BRIDGE_CORE_1202` | Use uma chave nova para o novo envio. |
| Mesma chave enquanto a primeira requisição ainda está em andamento | `409` `BRIDGE_CORE_1201` | Tente de novo com a mesma chave depois de uma pausa. |
| A primeira requisição falhou antes de gravar qualquer coisa | O Bridge libera a chave | Corrija a causa e tente de novo com a mesma chave. |
| A primeira requisição foi interrompida depois de gravar a mensagem | `409` `BRIDGE_CORE_1201` por até 24 horas | A mensagem pode existir. A API não tem operação para listar mensagens: peça a um Usuário do Bridge que confira a conversa antes de enviar de novo com uma chave nova. |

### Se a requisição for rejeitada

| Erro | O que fazer |
| --- | --- |
| `BRIDGE_TEMPLATE_0001` | Nenhum template de provedor do seu workspace tem esse `id`. Envie o `id` de um template de provedor do seu workspace. |
| `BRIDGE_CONVERSATION_0001` | A conversa não existe no seu workspace. Envie o `conversationId` de uma das suas conversas. |
| `BRIDGE_CONVERSATION_0007` | A conversa foi liberada. Inicie-a de novo com `POST .../conversations`, solicitando os mesmos contatos e linhas. |
| `BRIDGE_CONVERSATION_0011` | Um Agente está atendendo a conversa. Consulte-a com `GET .../conversations/{conversationId}` e tente de novo quando o `status` for `ACTIVE`. |
| `BRIDGE_CONVERSATION_0004` | A conversa não está ativa. Tente de novo só quando o `status` for `ACTIVE`. |
| `BRIDGE_CONVERSATION_0609` | A conversa ainda não tem template inicial e este template não é de marketing nem de utilidade. Envie um template de marketing ou de utilidade: ele passa a ser o template inicial. |
| `BRIDGE_CONVERSATION_0613` | Outra requisição está abrindo a conversa com seu template inicial, ou esse template ainda está sendo enviado. Tente de novo em alguns segundos: o bloqueio dura no máximo 120 segundos depois que o template inicial foi criado. Duas requisições que abrem ao mesmo tempo a mesma conversa pendente não podem ambas enviar: uma recebe este erro, ou `BRIDGE_CONVERSATION_0406` quando a outra reservou antes o período de espera do contato em um workspace que o tem. |
| `BRIDGE_CONVERSATION_0201` | A conversa não tem nenhum contato de WhatsApp. Envie para uma conversa que tenha um: `GET .../conversations/{conversationId}` lista seus participantes. |
| `BRIDGE_COMMERCIAL_CONSENT_0203` | Um contato não aceita mensagens iniciadas pelo Bridge. Não tente de novo: pare de enviar templates para esta conversa até que o contato volte a aceitar mensagens. A [referência de erros](/pt-br/error-codes#commercial-consent-error-codes) explica quando isso acontece. |
| `BRIDGE_CONVERSATION_0406` | O template é de marketing ou de utilidade e um contato da conversa está dentro do período de espera promocional do workspace: outro envio já o reservou. O Bridge conta os envios que registrou ou está registrando, não se o WhatsApp os entregou. `extra.contactIds` lista esses contatos e `extra.retryAfterSeconds` é a maior espera restante, também no header `Retry-After`. Nada foi enviado a nenhum contato. Tente de novo depois desse número de segundos. |
| `BRIDGE_TEMPLATE_0006` | O template não está aprovado para a linha e o idioma de pelo menos um contato de WhatsApp, ou a linha de um contato não tem conta do WhatsApp Business. Use um template aprovado para a linha e o idioma de cada contato da conversa. |
| `BRIDGE_TEMPLATE_0007`, `0009`, `0010` | Corrija os valores do template. A [referência de erros](/pt-br/error-codes#template-error-codes) descreve cada um. |
| `BRIDGE_TEMPLATE_0011`, `0012` | Corrija `template.media`: envie-o só para um template com cabeçalho de imagem ou de vídeo, com um `type` que corresponda e, com `mediaId`, um arquivo desse tipo. A [referência de erros](/pt-br/error-codes#template-error-codes) descreve cada um. |
| `BRIDGE_TEMPLATE_0013` | O template tem um cabeçalho de imagem ou de vídeo e não há arquivo para enviar. Envie `template.media` ou peça que um arquivo seja configurado no template. Quando `extra.expectedType` é `DOCUMENT`, o Bridge não pode enviar cabeçalhos de documento, com ou sem `template.media`: use outro template. |
| `BRIDGE_PRELOAD_FILE_0001` | O `mediaId` não é um arquivo do seu workspace. Faça o upload do arquivo como em [Enviar PDF e outros anexos](/pt-br/guides/send-attachments) e envie o `mediaId` que ele devolve. |
| `BRIDGE_PRELOAD_FILE_0002` | O arquivo ainda não pode ser usado. Se ainda está sendo enviado, termine o upload e tente de novo com o mesmo `mediaId`. Se o upload foi cancelado, faça o upload de um arquivo novo e envie o novo `mediaId`. |

Uma requisição com vários problemas é respondida com o primeiro que o Bridge encontra: corrija esse erro e envie de novo, porque outro pode aparecer. Uma requisição rejeitada com um destes códigos não enviou nada. Todos os códigos estão em [Códigos de erro](/pt-br/error-codes).
