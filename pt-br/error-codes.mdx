<a id="response-format"></a>

## Formato da resposta

Exemplo de resposta `Problem`. Consulte na referência do endpoint o status HTTP, o tipo de mídia e o esquema da resposta:

```json
{
  "title": "A template named in the onboarding override is missing values only the caller can provide",
  "status": 422,
  "detail": "A template named in the onboarding override is missing values only the caller can provide",
  "code": "BRIDGE_CONVERSATION_0604",
  "extra": {
    "templateId": "f0000040-0000-4000-8000-000000000040",
    "missingVariables": [{ "key": "delivery_date", "label": "Delivery date" }]
  },
  "instance": "https://api-connect-us.bridge.new/bridge/api/v1/workspaces/{workspaceId}/conversations",
  "traceId": "Root=1-6702b8c4-3f1a2b4c5d6e7f8091a2b3c4"
}
```

| Campo | Significado |
| ----- | ------- |
| `code` | Quando presente, o código estável de erro listado nesta página. **Escolha o tratamento por esse campo, não pelo título.** Erros de validação e de servidor podem omiti-lo. |
| `title` | Uma mensagem legível por pessoas. Ela pode ser mais longa que o título das tabelas abaixo; nunca use seu texto para identificar o erro |
| `status` | O código de status HTTP |
| `detail` | Mais detalhes sobre a ocorrência, quando disponíveis |
| `extra` | Contexto do erro legível por máquina, como IDs ou chaves envolvidos, quando disponível |
| `instance` | A URL da requisição |
| `traceId` | Inclua-o ao entrar em contato com o suporte |

<Note>
  Leia o esquema de resposta da operação chamada. Quando ele for `HTTPValidationError`, os detalhes de validação estarão em um array `detail`; cada entrada contém `loc` (onde), `msg` (o quê) e `type`. Outras respostas `422` documentadas usam `Problem` e podem incluir `code` e `extra`. Não presuma que todas as respostas `422` tenham o mesmo formato.
</Note>

<a id="parse-validation-errors-defensively"></a>

### Interprete erros de validação de forma defensiva

Aceite corpos de erro JSON tanto com `application/json` quanto com `application/problem+json`. Primeiro verifique o status HTTP; depois, examine o corpo:

1. Se `code` estiver presente, use a entrada correspondente desta página para escolher a ação.
2. Se `errors` for um array, leia suas entradas `loc`, `msg` e `type` como detalhes de validação.
3. Se `detail` for um array, interprete-o no formato `HTTPValidationError`. Um `detail` do tipo string é uma explicação, não uma lista de erros de campo.
4. Preserve `traceId`, o status e a URL da requisição para suporte. Não exija que `code` ou `extra` existam nem compare mensagens legíveis por pessoas como identificadores.

Um campo inválido e uma regra que relaciona vários campos não precisam ter o mesmo status. As regras do corpo outbound revisadas geram `400` com `BRIDGE_CORE_0103` quando `consent.status` é `GRANTED` sem `capturedAt`, ou quando `template.media` fornece ambos ou nenhum de `mediaId` e `url`. Tipos de campo ou UUIDs inválidos podem gerar, por sua vez, detalhes de validação de requisição com `422`. Interprete o status e o corpo do erro juntos; não exija um array `errors` para toda requisição inválida.

<a id="legacy-code-strings"></a>

### Códigos legados com sufixo

Alguns tratadores de erro legados acrescentam um nome simbólico a `code`, por exemplo, `BRIDGE_PRELOAD_FILE_0002 | PRELOAD_FILE_IS_PENDING`. Preserve o valor recebido completo para logs e suporte. Para consultar o catálogo, aceite um código simples conhecido ou sua forma legada reconhecida explicitamente; não compare `title` ou `detail`, não invente um código desconhecido nem reescreva o corpo da resposta. Esta revisão do código-fonte não confirmou de forma independente qual versão do tratador está implantada.

<Warning>
  **Compatibilidade de validação:** algumas respostas OpenAPI publicadas declaram `HTTPValidationError.detail[]` e `application/json`, enquanto o tratador compartilhado de erros da API revisado para esta documentação retorna detalhes de validação como `Problem.errors[]` com `application/problem+json`. Esta atualização editorial preserva as definições de resposta publicadas. Trate os dois formatos; a confirmação na API implantada continua pendente antes de adotar um deles como único formato aceito por um cliente gerado estrito.
</Warning>

<a id="decide-whether-to-retry"></a>

### Decida se deve tentar novamente

| Resultado | Ação |
| --- | --- |
| `400` ou `422` | Corrija a requisição usando o código e os erros de campo. Repetir os mesmos dados não corrige a validação. |
| `401` ou `403` | Confira credencial, workspace e permissões da integração correta. Mantenha as chaves da API REST no servidor. |
| `404` | Confirme o identificador e o workspace. Uma consulta que não encontra um Contato é diferente de uma entrada malformada. |
| `409` | Leia o código da operação: conversa existente, Agente indisponível e sessão não finalizada exigem soluções diferentes. Não habilite `forceSend` automaticamente. |
| `429` | Siga os [cabeçalhos de limite e as orientações de espera](/pt-br/rate-limits). |
| Timeout, desconexão da resposta ou `5xx` após uma gravação | Trate o resultado como incerto. Consulte o recurso afetado antes de reenviar: um erro não comprova que nenhum trabalho foi persistido. |

As orientações gerais de nova tentativa não acrescentam idempotência a um endpoint. Para reutilização outbound, recuperação e gravações parciais, veja [outbound de Agente e transferência](/pt-br/guides/agent-outbound). Custom Connections tem sua própria [referência de erros](/pt-br/lead-capture/errors) e não usa chave da API REST.

<a id="message-reply-errors"></a>

## Erros ao responder a uma mensagem

Para `POST .../messages`, as verificações revisadas da mensagem à qual você responde definem estas formas legadas adicionais:

- `BRIDGE_MESSAGE_0001 | MESSAGE_NOT_FOUND` (`404`): o Message indicado em `replyToMessageId` não foi encontrado.
- `BRIDGE_MESSAGE_0002 | MESSAGE_IS_NOT_ON_CONVERSATION` (`403`): a mensagem à qual você responde pertence a outra Conversation. Use uma da Conversation em que você enviará a mensagem.

Preserve o `code` completo, incluindo seu sufixo simbólico. Essas verificações se referem à mensagem à qual você responde, não ao `mediaId` do anexo.

<a id="file-upload-errors"></a>

## Erros de upload de arquivos

O fluxo de upload revisado define estes códigos legados. O sufixo faz parte do `code` recebido, não é um campo da requisição. Consulte o contrato de resposta da operação e mantenha a interpretação compatível acima.

A operação determina quais erros de arquivo se aplicam: `POST .../files` verifica os metadados e pode retornar os códigos `0003` ou `0004` abaixo. `POST .../messages` pode retornar `0001` ou `0002` quando o `mediaId` de um anexo não existe ou ainda está pendente. Os arquivos de templates outbound têm seu próprio tratamento de erros; não substitua `BRIDGE_AI_LEADSCOUT_0016` por esses códigos.

| `code` legado | Status | Ação |
| --- | --- | --- |
| `BRIDGE_PRELOAD_FILE_0001 \| PRELOAD_FILE_NOT_FOUND` | 404 | Confira o `mediaId` retornado e o upload referenciado. |
| `BRIDGE_PRELOAD_FILE_0002 \| PRELOAD_FILE_IS_PENDING` | 400 | O arquivo ainda está pendente. Confirme que o PUT terminou e aguarde o processamento do upload; não conclua que uma requisição de Message com falha não persistiu nenhum trabalho. |
| `BRIDGE_PRELOAD_FILE_0003 \| PRELOAD_FILE_INVALID_MIME_TYPE` | 400 | Corrija a combinação do tipo MIME e do `fileType` lógico. |
| `BRIDGE_PRELOAD_FILE_0004 \| PRELOAD_FILE_INVALID_NAME` | 400 | Informe um nome com uma extensão aceita para esse `fileType` lógico. |

<a id="agent-error-codes"></a>

## Códigos de erro de Agentes

Códigos de erro de operações de Agentes.

| Código | Título | Mensagem |
| ---- | -------------- | ------- |
| `BRIDGE_AI_AGENT_OUTBOUND_0001` | Agente não encontrado | O Agente não foi encontrado no workspace |
| `BRIDGE_AI_AGENT_OUTBOUND_0002` | Agente indisponível | O Agente não está disponível para outbound |
| `BRIDGE_AI_AGENT_OUTBOUND_0003` | Tipo de Agente não aceito | O tipo de Agente não é aceito para outbound |
| `BRIDGE_AI_AGENT_OUTBOUND_0004` | Agente sem canais | Nenhuma linha ativa de mensagens está vinculada ao Agente |
| `BRIDGE_AI_AGENT_OUTBOUND_0005` | Agente não atribuído ao canal | O Agente não está atribuído ao canal solicitado |
| `BRIDGE_AI_AGENT_OUTBOUND_0006` | Conversa controlada por outro Agente | A conversa ativa é controlada por outro Agente |
| `BRIDGE_AI_AGENT_OUTBOUND_0007` | Cursor inválido | O cursor de paginação está malformado ou pertence a outro workspace |

`POST .../agents/{agentId}/outbound` retorna `0001` e `0004` como `404`, `0002` e `0006` como `409`, e `0003` e `0005` como `422`.

- `0002`: o Agente é um rascunho ou não tem linha. `extra.reason` informa qual é o caso; o mesmo motivo aparece como `unavailableReason` em `GET .../agents`.
- `0006`: a conversa do Contato na linha selecionada pela requisição está sob o controle de outro Agente ou de um usuário do Bridge. Nada foi enviado. Libere-a com `POST .../conversations/{conversationId}/release`, usando `extra.conversationId`, e depois tente novamente. `extra` também contém `channelId` e, somente quando o controlador é um Agente, `controllingAgentId`. Quando o controlador é um usuário do Bridge, a chave está ausente, não é `null`.

`GET .../agents` retorna `0007` como `400` quando o `cursor` está malformado ou foi emitido para outro workspace. Recomece sem cursor. Mantenha o mesmo filtro `type` durante a paginação: um cursor emitido com um filtro `type` é rejeitado se a requisição informar outro `type`.

- `0007`: a conversa foi liberada e esta operação não a recupera. Inicie-a de novo com `POST .../conversations`, solicitando os mesmos Contatos e linhas: o Bridge recupera uma conversa liberada quando consegue.
- `0011`: um Agente está atendendo a conversa. Consulte-a com `GET .../conversations/{conversationId}` e tente de novo quando o `status` for `ACTIVE`.
- `0004`: a conversa não está ativa, por exemplo porque está bloqueada ou excluída. Confira o `status` e tente de novo só quando for `ACTIVE`.
- `0613`: o template inicial ainda está sendo enviado. Tente de novo em alguns segundos.

| `BRIDGE_PIPELINE_0004` | 409 | Registro já está na etapa | O registro já está na etapa da movimentação. Não há nada a fazer |
| `BRIDGE_PIPELINE_0101` | 409 | Conflito de revisão do registro | O registro mudou depois do `revision` que você enviou como `expectedRevision`. `extra.currentRecord` é o registro como está agora: decida de novo e tente outra vez com o `revision` dele |
| `BRIDGE_PIPELINE_0201` | 404 | Pipeline não encontrado | O pipeline não existe no seu workspace. [Liste os pipelines](/pt-br/api-reference/pipelines-api/listar-os-pipelines-de-um-workspace) para encontrar o id dele |
| `BRIDGE_PIPELINE_0301` | 403 | Pipelines desativados | Os pipelines não estão habilitados para o workspace. Fale com quem administra o workspace |
| `BRIDGE_PIPELINE_0305` | 422 | Contato incompleto | A etapa exige um contato completo. `extra.missing` diz o que falta: complete o contato e tente de novo |
| `BRIDGE_PIPELINE_0306` | 409 | Registro não está aberto | O registro está fechado. Reabra-o antes de movê-lo |
| `BRIDGE_PIPELINE_0307` | 409 | Registro não está fechado | Só um registro fechado pode ser reaberto |
| `BRIDGE_PIPELINE_0311` | 422 | Validação do registro falhou | O registro não é válido. `extra.errors` lista cada problema, cada um com `path`, `code` e `message` |
| `BRIDGE_PIPELINE_0314` | 422 | Motivo de fechamento desativado | O motivo de fechamento está desativado. Use um ativo do pipeline |
| `BRIDGE_PIPELINE_0315` | 422 | Motivo de fechamento não encontrado | O motivo de fechamento não existe no pipeline |
| `BRIDGE_PIPELINE_0317` | 403 | Entrada no pipeline desativada | O pipeline não aceita registros criados pela API |
| `BRIDGE_PIPELINE_0318` | 409 | Contato já tem registro aberto | O pipeline permite um registro aberto por contato e o contato já tem um. `extra.openRecordId` é esse registro: trabalhe nele |
| `BRIDGE_PIPELINE_0401` | 409 | Requisição idempotente em andamento | Uma requisição com esta `Idempotency-Key` ainda está em andamento. Tente de novo depois de uma pausa; se continuar falhando, tente com uma key nova |
| `BRIDGE_PIPELINE_0402` | 422 | Chave de idempotência reutilizada | A `Idempotency-Key` já foi usada com outra requisição. Use uma key nova para uma mudança nova |

Códigos de `BRIDGE_PIPELINE_0311` em `extra.errors[].code`:

| Código | Significado |
| ---- | ------- |
| `errRecordStage` | A etapa não está na versão do pipeline do registro, ou é uma etapa final na criação |
| `errRecordName` | O nome está ausente, em branco ou tem mais de 200 caracteres |
| `errRecordValue` | Um valor não corresponde ao tipo do seu atributo |
| `errRecordValueKey` | Uma chave de `values` não é um atributo do registro na versão do pipeline |
| `errRecordNoChange` | A atualização não muda nada |
| `errReasonNote` | `reasonNote` é longo demais ou foi enviado sem `reasonId` |
| `errReasonOnlyFinal` | Um motivo ou nota de fechamento foi enviado em uma movimentação para uma etapa aberta |

As operações de pipelines também respondem `403` `BRIDGE_CORE_0301` quando o `workspaceId` do caminho não é o workspace da API Key, `404` `BRIDGE_EXTERNAL_0001` quando o contato não existe, `404` `BRIDGE_WORKSPACE_0001`, `400` `BRIDGE_CORE_0104` para um cursor inválido e `429` `BRIDGE_RATE_LIMIT_0001`.

Códigos das operações de canais de provedor.

| Código | Título legível | Mensagem |

<a id="rate-limit-error-codes"></a>

## Códigos de limite de requisições

Códigos retornados quando um workspace excede a cota de requisições. Veja em [limites de requisições](/pt-br/rate-limits) a cota, os cabeçalhos e um cliente que controla seu ritmo.

| Código | Título | Mensagem |
| ---- | -------------- | ------- |
| `BRIDGE_RATE_LIMIT_0001` | Requisições em excesso | O workspace esgotou a cota de requisições da janela atual |

Esse é o único código que deve ser repetido automaticamente, e apenas após o intervalo informado no cabeçalho `Retry-After`. Falhas de autenticação não são erros de limite, e repeti-las periodicamente não resolverá o problema.

<a id="request-error-codes"></a>

## Códigos de erro de requisição

Códigos retornados antes de executar a operação, quando a própria requisição não pode ser processada. Veja no [histórico de alterações](/pt-br/changelog) os parâmetros que um endpoint deixará de aceitar.

| Código | Título | Mensagem |
| ---- | -------------- | ------- |
| `BRIDGE_CORE_0101` | Formato de campo inválido | O formato do campo é inválido; forneça um valor válido |
| `BRIDGE_CORE_0102` | Campo obrigatório ausente | A requisição não contém campos obrigatórios; revise a operação |
| `BRIDGE_CORE_0103` | Requisição inválida | A requisição é inválida; revise o corpo e os parâmetros |
| `BRIDGE_CORE_0104` | Cursor inválido | O cursor fornecido é inválido; use um cursor obtido em uma resposta anterior |

Nenhum desses erros deve ser repetido sem alterações. `detail` descreve o problema e, quando possível, identifica o campo ou parâmetro incorreto; a mesma requisição falhará da mesma forma até ser corrigida.

| ---- | -------------- | ------- |
| `BRIDGE_TEMPLATE_0001` | Template de provedor não encontrado | Nenhum template de provedor encontrado para o workspace e nome informados |

| Código | Status | Título | Quando acontece e o que fazer |
