Os webhooks do Bridge entregam payloads estruturados em JSON sempre que ações específicas ocorrem no workspace. Cada evento segue um esquema consistente para facilitar a interpretação e a validação.

---

<a id="common-event-structure"></a>

## Estrutura comum dos eventos

O exemplo abaixo ilustra o envelope comum; `"string"` representa um tipo, não um valor de evento para enviar. Leia os exemplos específicos de cada família a seguir. Não presuma que `eventId` seja globalmente único entre famílias de notificação.

```json
{
  "eventId": "string",
  "eventType": "string",
  "entity": "string",
  "workspaceId": "string",
  "timestamp": "string",
  "payload": {}
}
```

## Atualizações de tarefas

<span className="bridge-version-badge">v1</span>

Disparadas quando tarefas são criadas ou seu estado muda, incluindo status, atribuição e lembretes.

Os payloads variam conforme o tipo de evento. O campo `details` descreve o que mudou naquele evento específico.

<span className="bridge-version-badge">v1</span>

Disparadas quando registros de contatos são criados, atualizados ou excluídos.

<Tabs>
  <Tab title="Tipos de evento">
    | Tipo de evento | Descrição |
    | ----------------- | ---------------------------- |
    | `contact.created` | Um novo contato foi criado |
    | `contact.updated` | Um registro de contato foi atualizado |
    | `contact.deleted` | Um registro de contato foi excluído |
  </Tab>
  <Tab title="Exemplos de payload">

<a id="call-notifications"></a>

## Notificações de chamadas

<span className="bridge-version-badge">v1</span>

Disparadas à medida que uma chamada percorre seu ciclo de vida. O Bridge emite no máximo um webhook por fase do ciclo, por chamada. Assim, a integração recebe uma sequência clara de quatro fases — criação, toque, início e término — em vez de todas as transições intermediárias gravadas internamente.

A fase atual pode ser determinada pelo estado da chamada e pelo status dos participantes:

| Fase | Como identificar |
| -------- | ------------------------------------------------------------------------ |
| created | O estado é CREATED e nenhum participante ingressou ou está chamando |
| ringing | Um participante tem status RINGING e ninguém ingressou ainda |
| started | O estado é STARTED e dois participantes estão JOINED |
| finished | O estado é FINISHED |

Chamadas não atendidas pulam a fase de início: a integração recebe apenas created, ringing e finished.

Quando uma chamada termina, o Bridge processa a gravação em um fluxo assíncrono de transcrição por IA. Quando a transcrição fica pronta, a integração recebe um evento adicional `call.transcription.created` com o texto completo dividido em segmentos por interlocutor e com marcação de tempo. Esse evento chega **depois** de `call.updated (finished)`, normalmente de alguns segundos a poucos minutos depois, conforme a duração da chamada. A diarização, que identifica os interlocutores, depende da qualidade da fonte de áudio; gravações mono podem produzir um único rótulo de interlocutor para toda a transcrição.

<Tabs>
  <Tab title="Tipos de evento">
    | Tipo de evento | Descrição |
    | ----------------------------- | ----------------------------------------------------------- |
    | `call.created` | Uma nova chamada foi provisionada |
    | `call.updated` | Uma fase da chamada mudou: toque, início ou término |
    | `call.transcription.created` | A transcrição por IA de uma chamada finalizada está pronta |
  </Tab>

  </Tab>
  <Tab title="Exemplo de payload">
    ```json
    {
      "eventId": "evt_email_001",
      "eventType": "email.updated",
      "entity": "email",
      "workspaceId": "ws_123",
      "timestamp": "2026-05-04T00:45:31.261Z",
      "payload": {
    ```

<a id="notes"></a>

## Observações

- O Bridge pode acrescentar novas categorias de eventos no futuro.
- Sempre verifique o campo de tipo de evento para escolher qual tratador executar.
- Configure e dê suporte à versão selecionada para cada assinatura de evento. O envelope comum não declara um campo universal `version`; não o exija nem o invente. Veja [recebimento de eventos](/pt-br/webhooks/receive-events) para tratar duplicatas e ordenação.
